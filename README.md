# Pulse

Watchdog для сервисов на Railway и Vercel. Опрашивает деплои и живые URL,
при падении присылает в Telegram карточку с причиной, вытянутой из логов, и
кнопками «Логи», «Заглушить», «Перезапустить».

## Что он на самом деле решает

Написать «раз в минуту дёргай URL и пиши в телегу, если 500» — час работы.
Через день такой бот превращается в шум, который перестают читать, и тогда
он хуже, чем ничего.

Поэтому ядро Pulse — не пробы, а `pulse/alerting.py`:

- **Подтверждение.** Алерт уходит после N подряд неудачных проверок. Один
  таймаут сети никого не будит.
- **Дедуп.** Пока инцидент открыт, повтор не шлётся — вместо него редкое
  напоминание по cooldown.
- **Мьют.** Таргет можно заглушить на срок, не выключая проверку; мьют
  снимается вместе с закрытием инцидента.
- **Отдельный статус «не знаю».** Протухший токен и лимит API — это не
  падение сервиса. Такой результат не двигает счётчики и не закрывает
  открытый инцидент.

Состояние лежит в SQLite, поэтому перезапуск контейнера не рассылает алерты
по инцидентам, о которых уже сообщили.

## Что проверяется

| Источник | Что смотрит | Что ловит |
|---|---|---|
| HTTP | код ответа, задержка, подстрока в теле | то, что видит пользователь |
| Railway | статус последнего деплоя в окружении | `FAILED`, `CRASHED` |
| Vercel | `readyState` последнего production-деплоя | `ERROR`, `CANCELED` |

HTTP-проба нужна даже там, где есть Railway: деплой со статусом `SUCCESS` и
приложение, отвечающее 502, — разные вещи. И наоборот, сломанная выкладка на
Vercel не видна снаружи: на домене просто остаётся прошлая версия.

## Разбор логов

При подтверждённом падении сервиса на Railway Pulse тянет хвост логов деплоя
и просит Claude назвать причину. Ответ приходит по схеме (`pulse/triage.py`),
а не свободным абзацем, поэтому в карточку попадают отдельно причина, строка
лога, на которой она основана, и первое действие.

Промпт обязан признаваться в незнании: если в логах причины нет,
`confidence: low` честнее выдуманного объяснения. Падение триажа не роняет
алерт — сообщение о том, что сервис лежит, важнее объяснения почему.

## Запуск

```bash
pip install -e ".[dev]"
cp .env.example .env          # токены
cp targets.yml.example targets.yml
pulse --once                  # один прогон, проверить конфигурацию
pulse                         # цикл проверок + бот
```

`targets.yml` лежит в репозитории намеренно: список сервисов меняется вместе с
инфраструктурой, и его история в git полезна. Секреты туда не попадают.

Railway-токен нужен аккаунтный или workspace — проектный ходит по другому
заголовку и видит только своё окружение.

## Деплой на Railway

```bash
railway up
```

Смонтируйте volume в `/app/data` и задайте `PULSE_DB_PATH=/app/data/pulse.db`.
Без volume состояние инцидентов обнуляется на каждом деплое, и Pulse повторно
рассылает алерты по уже известным падениям.

## Команды бота

Бот отвечает только владельцу — `PULSE_TELEGRAM_CHAT_ID`.

- `/status` — текущее состояние всех таргетов и последние инциденты
- `/mute <таргет> <минуты>` — заглушить сервис

Кнопка «Перезапустить» под алертом уводит на отдельное подтверждение: это
действие на проде, и случайное касание в кармане не должно его запускать.

## Тесты

```bash
pytest
```

29 тестов на ядро: политика алертинга (флаппинг, дедуп, cooldown, мьют,
неизвестный статус), персистентность состояния и жизненный цикл инцидентов,
HTTP-проба на моках транспорта. Пробы Railway и Vercel против живых API не
тестируются.
